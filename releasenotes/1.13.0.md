## Engine
__BREAKING CHANGE__: ([#10667,#10202](https://github.com/defold/defold/pull/12367)) __'Remove the support for LiveUpdate auto mount'__ by JCash
⚠️ This removes the deprecated feature of LiveUpdate auto mounts.
From now on, developers must always choose their mounts when starting the game.

Note that the returned mount names now also are hashes (previously strings):
```lua
 pprint("MOUNTS", liveupdate.get_mounts())
```
returns
```lua
DEBUG:SCRIPT: MOUNTS,
{ --[[0x119667bf0]]
  1 = { --[[0x119667c50]]
    name = hash: [liveupdate],
    uri = "zip:/device/path/to/acchives/liveupdate.zip",
    priority = 5
  },
  2 = { --[[0x119667d50]]
    name = hash: [_base],
    uri = "archive:build/default/game.dmanifest",
    priority = -10
  }
}
```

__BREAKING CHANGE__: ([#11622](https://github.com/defold/defold/pull/12220)) __'Removed support for the `js-web` (asmjs) build from the engine'__ by AGulev
In this version, support for the js-web (asmjs) platform in the engine has been removed,[ as previously announced](https://forum.defold.com/t/removing-collada-support-and-the-asm-js-platform/82506).

This means `bob.jar` no longer supports `js-web` as a platform or architecture. Make sure your build scripts and CI have been updated accordingly.

__BREAKING CHANGE__: ([#12366](https://github.com/defold/defold/pull/12369)) __'Removed support for old LiveUpdate format'__ by JCash
⚠️ This removes support for our very old mutable LiveUpdate format, which managed individual files and manifests directly.
Going forward, we recommend using our LiveUpdate with "zip" mounts, allowing you to mount your downloaded .zip files.
If individual files are necessary, you can also use the "file" mount type which mounts a folder.

__BREAKING CHANGE__: ([#9072,#5666](https://github.com/defold/defold/pull/12377)) __'Component primitive order unification'__ by Jhonnyg
⚠️ BREAKING CHANGE ⚠️

The vertices for the `sprite`, `gui`, `tilegrid` and `particle` components are now unified with the rest of the components. The engine is now using counter-clockwise ordering of the vertices so that the normal of the primitive is pointing towards the camera. This means that you can use the same face culling parameters for all components.

Regarding breaking change:
This should only have an impact if you are using face culling for your components. In the default render script, we have enabled backface culling only for models but if your project is using backface culling for other components you might have to switch the front/back face using `render.set_cull_face(graphics.FACE_TYPE_BACK)`. The default cull face mode is FACE_TYPE_BACK, so you can also just remove the `render.set_cull_face` call

__NEW__: ([#9100](https://github.com/defold/defold/pull/9208)) __'Material and compute script modules'__ by Jhonnyg
Two new script modules have been added to the engine: `material` and `compute`.

These modules expose runtime inspection and mutation APIs for material and compute resources, making it possible to read and update constants, samplers, textures, and material vertex attributes from Lua.

## Added Script Functions

### `material`

#### Inspect Material Resources

```lua
local attributes = material.get_vertex_attributes("/my_material.materialc")
-- attributes contain:
-- {
--     {
--         name = hash("attribute_name"),
--         value = vmath.vector4(...), -- or vmath.vector3, vmath.matrix4, number, or table
--         normalize = false,
--         data_type = graphics.DATA_TYPE_FLOAT,
--         coordinate_space = graphics.COORDINATE_SPACE_WORLD,
--         semantic_type = graphics.SEMANTIC_TYPE_COLOR
--     }
-- }

local samplers = material.get_samplers("/my_material.materialc")
-- samplers contain:
-- {
--     {
--         name = hash("sampler_name"),
--         type = graphics.TEXTURE_TYPE_2D,
--         u_wrap = graphics.TEXTURE_WRAP_REPEAT,
--         v_wrap = graphics.TEXTURE_WRAP_REPEAT,
--         min_filter = graphics.TEXTURE_FILTER_LINEAR,
--         mag_filter = graphics.TEXTURE_FILTER_LINEAR,
--         max_anisotropy = 1
--     }
-- }

local constants = material.get_constants("/my_material.materialc")
-- constants contain:
-- {
--     {
--         name = hash("constant_name"),
--         type = material.CONSTANT_TYPE_USER,
--         value = vmath.vector4(...) -- only for user constants; arrays return a table of values
--     }
-- }

local textures = material.get_textures("/my_material.materialc")
-- textures contain:
-- {
--     {
--         path = hash("/some_texture.texturec"), -- only when resource-backed
--         handle = hash(...),
--         width = 128,
--         height = 128,
--         depth = 1,
--         mipmaps = 1,
--         type = graphics.TEXTURE_TYPE_2D,
--         flags = graphics.TEXTURE_USAGE_FLAG_SAMPLE,
--         page_count = 1
--     }
-- }
```

#### Update Material Resources

```lua

    attribute_name = {
        value = vmath.vector4(1, 0, 0, 1),
        data_type = graphics.DATA_TYPE_FLOAT,
        semantic_type = graphics.SEMANTIC_TYPE_COLOR,
        coordinate_space = graphics.COORDINATE_SPACE_WORLD,
        normalize = false
    },
    attribute_a = { value = vmath.vector4(1, 0, 0, 1) },
    attribute_b = { value = vmath.vector3(0, 1, 0) }
})

material.set_samplers("/my_material.materialc", {
    sampler_name = {
        min_filter = graphics.TEXTURE_FILTER_LINEAR,
        mag_filter = graphics.TEXTURE_FILTER_LINEAR,

        v_wrap = graphics.TEXTURE_WRAP_REPEAT,

        value = vmath.vector4(1, 2, 3, 4),

    }
})

    sampler_name = "/some_texture.texturec"
})
```

__FIX__: ([#11197](https://github.com/defold/defold/pull/12394)) __'Fix Base64Decode to handle input without padding'__ by singhvishalkr
When decoding base64 strings that lack padding characters, `dmCrypt::Base64Decode` returns nil. This happens because mbedTLS's base64 decoder strictly requires padding, but many systems (particularly JWT implementations) omit padding per RFC 4648 section 3.2 which states that padding is not always required.

This issue can be observed while using the crypt extension with Nakama's JWT tokens. The server sends tokens without padding, and the decode fails silently.

The fix adds the missing `=` characters before passing the input to mbedTLS when the input length is not a multiple of 4. In addition, a test cases covering strings with and without padding was added to prevent regression.

The change should not affect consoles since it only modifies the mbedTLS path.

__BREAKING CHANGE__: ([#12414](https://github.com/defold/defold/pull/12414)) __'Fixes model transform inconsistencies between the editor and runtime for imported glTF/glb models'__ by Jhonnyg
#### Model re-centering during import ⚠️ BREAKING CHANGE ⚠️
We have removed the automatic model re-centering step from the Bob model import pipeline so imported glTF model positions are not altered. It also adjusts model transform handling so skinned/bone-parented meshes preserve local transforms while rigid meshes keep their flattened world placement. Both of these changes takes Defold closer to a "what you see is what you get" approach for 3D content.

The re-centering means that If your 3D content suddenly changes positions / orientation, this means that the content needs to be modified in an authoring package (e.g Blender) and then re-exported to .glb again. Most projects should be unaffected by this change, but there _is_ a change in behaviour when importing models now in order to fix other incorrectly placed objects.

#### Editor vs runtime preview inconsitency
The editor preview now mirrors the runtime transform behaviour more closely: models with assigned skeletons use skeleton-relative transforms, while models without skeleton resources use their local model transforms, with bounds updated to match the selected transform path.

#### Runtime GPU skinning fixes
Runtime rig/model handling was also adjusted so parentless root bones keep the inherited ancestor transform from the imported skeleton, and skinning matrices are only applied when the model is actually animating.

__NEW__: ([#11995](https://github.com/defold/defold/pull/12285)) __'Add `/eval` endpoint to editor server'__ by vlaaad
Now, the editor exposes a local, authenticated `/eval` endpoint for evaluating Lua code in the editor Lua runtime.

Simplest example:

```sh
curl \
  "http://localhost:$(cat .internal/editor.port)/eval" \
  -H "Authorization: Bearer $(cat .internal/editor.token)" \
  --data "print('Hello from Lua') return 1, 'two', true"
# Hello from Lua
# => 1
# => two
# => true
```

Because `/eval` can run commands through `editor.execute`, requests must include the token from `.internal/editor.token`. This limits access to clients that also have filesystem access.

```sh
curl \
  "http://localhost:$(cat .internal/editor.port)/eval" \
  -H "Authorization: Bearer $(cat .internal/editor.token)" \
  --data "editor.execute('git', 'status', '--short', { reload_resources = false })"
#  M game.project
```

Security is documented in `openapi.json`, so the only URL your coding agent needs is still `http://localhost:$(cat .internal/editor.port)/openapi.json`. For example:

  - HTTP APIs via `http`, including `http.request` and `http.server.route`/`response`
