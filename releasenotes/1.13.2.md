__NEW__: ([#12525,#9656,#8686](https://github.com/defold/defold/pull/12923)) __'Add Bullet3D Lua API'__ by AGulev
Adds a `bullet3d` Lua API for accessing and controlling Defold’s 3D physics worlds, collision objects, rigid bodies, shapes, and constraints. Scripts can now create hinge and other 3D joints, modify body and shape properties, inspect contacts and overlaps, and perform immediate or deferred ray and convex-shape casts, including closest-hit queries.

- `bullet3d` — retrieve the current world, collision objects, rigid bodies, and bundled Bullet version.
- `bullet3d.world` — configure gravity, enumerate objects, perform overlap and contact queries, and run immediate or deferred ray and convex-shape casts.
- `bullet3d.collision_object` — control transforms, activation, friction, restitution, CCD, flags, and collision filters.
- `bullet3d.rigid_body` — control mass, inertia, velocity, damping, gravity, factors, sleeping, forces, impulses, and AABBs.
- `bullet3d.shape` — inspect and modify sphere, box, capsule, and convex-hull geometry and local transforms.
- `bullet3d.constraint` — create, configure, query, and destroy 3D constraints, including limits, motors, and springs.

__NEW__: ([#11036](https://github.com/defold/defold/pull/12613)) __'Add sample count setting for multisampled render target attachments'__ by Jhonnyg
Added configurable FSAA sample counts to render targets and implemented multisampled render targets with automatic color resolving. The sample count applies to all color, depth, and stencil attachments in the render target.

Example

```lua
local target = render.render_target({
    sample_count = 4,

    [graphics.BUFFER_TYPE_COLOR0_BIT] = {
        format = graphics.TEXTURE_FORMAT_RGBA,
        width = 1280,
        height = 720
    },

    [graphics.BUFFER_TYPE_DEPTH_BIT] = {
        format = graphics.TEXTURE_FORMAT_DEPTH,
        width = 1280,
        height = 720
    }
})
```

The same render-target-level sample_count setting is available for .render_target resources in the editor.
Requested sample counts are normalized to a value supported by the active graphics adapter. The effective value is available through `resource.get_render_target_info()`.

__NEW__: ([#12816](https://github.com/defold/defold/pull/13010)) __'Create a constant buffer snapshot when issuing render.draw'__ by Jhonnyg
Fixed an issue where render.draw() and render.dispatch_compute() is reusing and modifying the same buffer between submissions. This caused earlier commands to observe its final values instead of the values present when submitted.

We now generate a snapshot of the constant-buffer data when each command is queued. Every draw or compute dispatch now uses the constants supplied at submission time and not the "last seen" constant values.

__NEW__: ([#13145](https://github.com/defold/defold/pull/13146)) __'Removed use of deprecated browser `unload` event'__ by britzl
The browser `unload` event is about to be fully deprecated in Chrome. In Chrome 152 the top-50 websites and 80% of all page loads will treat `unload` as deprecated. Furthermore, Chrome reports it as a `Permissions policy violation`. This change replaces use of the `unload` event in the engine with `pagehide`.

__FIX__: ([#12780](https://github.com/defold/defold/pull/12783)) __'Do not reverse hash generated gui node ids'__ by AGulev, britzl
It is possible to run out of memory during long debug sessions if the game is cloning and deleting large amounts of gui nodes. The reverse hash table will in this case constantly grow and run out of memory when SetCapacity() is called. To avoid this situation generated node ids are no longer stored in the reverse hash lookup table.

__FIX__: ([#12896](https://github.com/defold/defold/pull/12896)) __'Fix sound exhaustion when Web Audio is unavailable'__ by AGulev

__FIX__: ([#13032](https://github.com/defold/defold/pull/13040)) __'Compute shaders not working on win32'__ by Jhonnyg
Fixed a few issues related to OpenGL compute shader support on Windows - compute shader support was compiled out of the Windows OpenGL graphics library. After enabling it, several existing OpenGL backend issues prevented compute output from rendering correctly:

* Compute programs did not initialize their resource-binding metadata, causing constants such as uniform-buffer members to be reported as missing.
* Storage-image detection relied on OpenGL’s active-uniform iteration order. This order is not guaranteed and could cause sampled textures and storage images to be bound to the wrong units.

__FIX__: ([#13012](https://github.com/defold/defold/pull/13014)) __'Syncronize getting native window for android when using vulkan'__ by Jhonnyg
Fixed an issue where using Vulkan on Android, the engine could crash during startup when the application lifecycle changed while the Vulkan surface was being created, for example if the app was paused or the screen was locked immediately after launch. The Vulkan backend used the current ANativeWindow without retaining it or verifying that it remained current. Android could destroy or replace that window concurrently, leaving Vulkan surface creation operating on a stale native-window pointer.

The fix moves Android window lifecycle handling into GLFW, which now waits until the application is resumed and a valid window is available, retains the window during Vulkan surface creation, and verifies afterward that it is still current. If the lifecycle changed during creation, the stale Vulkan surface is destroyed and creation is retried with the new window.
