glTF model loading profile

DDF decoding dominates model/mesh preparation. Texture acquisition dominates complete synchronous resource loads. These are actual engine resource loads of all 104 compiled example models, with a hidden Metal window.

Measured totals

Median of five sweeps, with one warmup per mode. All 1,040 measured model loads succeeded. The synchronous sweep takes 2,600.3 ms (range 2,566.7–2,620.4 ms); async takes 2,256.7 ms (2,249.7–2,272.6 ms). Startup, release, and frame cleanup are outside these load intervals.

Repeated-field counting and the dry decode together consume about 57% of DDF time. The final decode consumes about 42%; allocation/setup is under 1%. The decoder traverses scalar vertex streams for multiple passes; this is more expensive than repacking them into interleaved vertices.

Optimization priorities

First investigate storing bulk geometry as packed binary buffers, or reducing DDF counting/dry-run traversal. DDF is about 92% of model/mesh preparation. Moving vertex interleaving to Bob can remove about 16 ms across this set, around 2% of that path. Texture loading warrants a separate texture/transcoding profile.

Metal uses shared buffers here: the measured buffer API calls allocate and memcpy CPU-visible memory. They do not measure first-draw GPU time or a discrete-GPU transfer.

Method

  • Apple M5 Max, 18 logical cores, 128 GiB RAM; macOS 27.0.1; arm64 / Metal. Isolated RelWithDebInfo engine build; -O2 verified in compilation commands.
  • 104 compiled .modelc resources, 285.63 MiB of mesh-set files; 2,247 mesh buffer pairs; 5,837,121 vertices; 402.12 MiB vertex buffers and 44.47 MiB index buffers created per sweep.
  • Each model and its dependencies are released before the next; warm OS filesystem and Metal shader caches. Loose files, no archive decompression. Model/mesh work excludes file reads, materials, textures and rig/animation dependencies.
  • Sync uses dmResource::Get. Async uses NewPreloader / UpdatePreloader to completion, then Get. The preloader is pumped continuously without frame pacing. This isolates resource loading and excludes collection/gameobject instantiation, UI and rendering.
  • Temporary timers surround ResModelPreload / ResMeshSetPreload, DDF internal passes, FlattenMeshes, CreateVertexData, scratch allocation, buffer creation and dependency Get calls. No per-vertex timing calls. Logged durations are elapsed time, not sampled CPU time.
  • Control: three sweeps per mode with probes removed. Median sync: 2,513.2 ms; async: 2,265.8 ms. Instrumented sync is 3.5% higher; async differs by -0.4%, within observed variation. Individual phase values are not adjusted for overhead.
  • Uses the existing compiled snapshot of committed examples f837ae30fe. User edits/untracked models are excluded and untouched. No Bob rebuild was needed. All five temporary source edits were restored byte-for-byte; the main engine build was kept separate.
