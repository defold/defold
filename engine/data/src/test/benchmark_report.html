Detailed comparison

Exact values and additional metrics

Inspect timing, heap totals, peaks and live blocks for any current workload. Main bars use separate components for Flecs and Bevy; tables also show their complete-struct variants.

All backends instantiate mutable values. Defold additionally retains loaded/added defaults for reset. Flecs/Bevy restore between tests from fixture data outside measured store memory. Resource reset/unload has no equivalent measured Flecs/Bevy contract.
Method and scope

Same workload, explicit storage differences

Defold

Fixed-stride mutable rows share property metadata. Queries bind property paths and kinds once, then use public typed field pointers and row iteration under a structural lock.

Registrations of a loaded resource share dense runtime tables. Reset/unload groups use pooled records and row indices. Source metadata and defaults remain in the resource; replaced strings and containers belong to each registration.

Flecs

Main results use separate Position, Health, Velocity and Light components, with concrete-type tags and the same logical identities.

Official C query APIs supply component arrays, followed by native member access. Explosion declares health read/write and position read-only; health/position scans declare both read-only. Values are overwritten in place.

Bevy

Main results use separate components with default table storage and normal change tracking.

The standalone ECS crate uses QueryState iteration and typed component references. No renderer or scheduler is included. Writes modify current values; the measured store retains no initial-value baseline.

Complete-struct variants store one native component per concrete type, with inline Light fields and a typed adapter for shared properties. Both layouts are measured in the same run; the main charts use separate components.

Workloads and timing

  • Deterministic seed 0x12345678. Backend order rotates; one warmup is discarded. Read queries use five passes; writes use one.
  • Explosion scans health and position, subtracting 25 health within radius 50 of the origin, clamped at zero. There is no spatial index. Shuffled position visits every instance once and increments X by one.
  • Query setup is defined beside each C++ case. Creation and field binding are measured separately from traversal. Fixture generation, validation and resets between tests are outside timing.
  • Insertion includes allocation and live-query maintenance. Source blobs are prepared before measurement; these tests do not time disk I/O, serialization or resource validation.
  • C++ and Rust run sequentially in separate processes, reversing process order between fixture layouts. Compiler and API differences are included.

Memory accounting

  • Timing binaries contain no allocation tracking. Separate memory binaries track C++/Flecs allocation hooks and Bevy's Rust global allocator.
  • Requested live bytes include unused library capacity. Allocation requests count heap allocations and resizes, including allocations later freed in the same phase.
  • Peaks begin at operation entry. Resize peaks exclude the allocator's transient internal copy.
  • Fixture inputs, caller-owned ID arrays and shared resource blobs are recorded separately and excluded from library charts. Allocator headers/rounding, stack/static storage, libc internals and process RSS are excluded.
  • Defold runtime-created rows retain added-value defaults; resource instances share their defaults. Flecs/Bevy use fixture data for reset. These memory contracts differ.
Validation and measurement limits

Only macOS arm64 is measured. These are warm microbenchmarks of the stated APIs and layouts. CPU model was unavailable in the measurement environment. No hardware-counter or cold-cache study, Unity execution, Bob/gamesys integration or equivalent cross-library reset/unload benchmark is included.
